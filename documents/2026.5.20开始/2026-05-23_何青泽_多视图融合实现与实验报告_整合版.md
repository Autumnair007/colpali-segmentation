# 何青泽：免训练多视图得分融合实现与实验报告（整合版）

> 日期：2026-05-23  
> 版本定位：整合版，用于替代前面分散的“多视图修改方案”“实验记录”“最小提交建议”中的技术实现部分。  
> 当前结论：本阶段最适合作为一个小而清楚的 PR 提交，主题是新增免训练多视图得分融合 baseline，并在 clean 数据上验证它不会破坏原始检索流程。

## 1. 当前方案定位

当前已经实现的是：

```text
免训练多视图得分融合
training-free multi-view score fusion
```

它不是训练模型，也不是完整的真实退化鲁棒性结论。它更准确的定位是：

```text
冻结 ColQwen2 编码器条件下的测试时多视图检索 baseline。
```

当前没有真实退化图，也没有接入组内后续退化数据，所以本阶段只做 clean 数据稳定性验证。也就是说，本阶段主要证明：

```text
新增 multiview 代码不会破坏原始 clean 检索结果。
```

暂时不能声称：

```text
已经证明该方法能抵抗真实退化。
```

等后续真实 degraded/restored 图到位后，可以直接复用当前 `multiview` 入口继续验证鲁棒性。

## 3. 本次代码改动

### 3.1 新增文件

新增：

```text
experiments/multiview.py
```

主要负责：

1. 定义可用 view。
2. 对单张图或一批图生成对应 view。
3. 校验 view 名称是否合法。
4. 归一化 weighted fusion 权重。
5. 对多个 view 的 score matrix 做融合。

当前支持的 view：

```text
identity
nlmeans
gaussian
wiener
```

默认权重：

```text
identity: 0.70
nlmeans: 0.10
gaussian: 0.10
wiener: 0.10
```

这样设计的原因是当前先在 clean 数据上验证稳定性，因此需要以 `identity` 为 anchor，避免轻量图像处理对 clean 图造成过大扰动。

### 3.2 修改文件

修改：

```text
experiments/run_benchmark.py
```

新增能力：

```text
--condition multiview
--views identity nlmeans gaussian wiener
--fusion max | mean | weighted
--local-files-only
--model
--processor
--device
--score-batch-size
```

其中：

| 参数 | 作用 |
| --- | --- |
| `--condition multiview` | 启用多视图得分融合流程 |
| `--views` | 指定使用哪些图像视图 |
| `--fusion` | 指定 score-level 融合方式 |
| `--local-files-only` | 只使用本地缓存，避免重复下载 |
| `--model` | 指定模型路径，例如 `./colqwen2-v1.0` |
| `--processor` | 指定 processor 路径 |
| `--device` | 指定 GPU，例如 `cuda:1` |
| `--score-batch-size` | 控制 MaxSim scoring 的 batch size，降低显存压力 |

新增：

```text
tests/test_multiview.py
```

覆盖内容：

## 4. 代码逻辑说明

### 4.1 Query 只编码一次

无论有多少个 document view，query 都只编码一次：

```text
query -> processor.process_queries() -> model -> query_vectors
```

这样避免重复计算 query embedding。

### 4.2 Document 按 view 分别编码

对每个 view，文档图像都会单独处理和编码：

```text
image -> view_preprocess -> processor.process_images() -> model -> document_vectors_view
```

例如四视图时：

```text
identity document vectors
nlmeans document vectors
gaussian document vectors
wiener document vectors
```

### 4.3 每个 view 单独计算 MaxSim

每个 view 都会和同一份 query vectors 计算一次 MaxSim：

```text
scores_identity = score_multi_vector(query_vectors, doc_vectors_identity)
scores_nlmeans  = score_multi_vector(query_vectors, doc_vectors_nlmeans)
scores_gaussian = score_multi_vector(query_vectors, doc_vectors_gaussian)
scores_wiener   = score_multi_vector(query_vectors, doc_vectors_wiener)
```

每个 `scores_*` 的形状都是：

```text
[num_queries, num_docs]
```

这点也方便后续和郭明坤的 late interaction 加权机制对齐：不管内部怎么做，最终最好都输出同样形状的 score matrix。

### 4.4 Score-level fusion

当前是在分数层做融合，不是在 embedding 层直接融合。

支持三种方式：

```text
max
mean
weighted
```

`max`：

```text
scores = max(scores_view_1, scores_view_2, ...)
```

适合后续真实退化实验，因为某些 view 可能刚好恢复了某类退化信息。

`mean`：

```text
scores = average(scores_view_1, scores_view_2, ...)
```

作为简单平均 baseline。

`weighted`：

```text
scores = 0.70 * scores_identity
       + 0.10 * scores_nlmeans
       + 0.10 * scores_gaussian
       + 0.10 * scores_wiener
```

当前 clean 稳定性实验默认使用 `weighted`，因为 identity 权重较高，风险更低。

## 5. 这次没有做什么

当前实验没有做这些事情：

1. 没有使用真实退化图。
2. 没有运行 `DegradationPipeline` 做 synthetic degraded benchmark。
3. 没有做运动模糊、噪声、JPEG、倾斜等退化模拟实验。
4. 没有训练 ColQwen2。
5. 没有修改模型权重。
6. 没有做完整 embedding 一致性分析。
7. 没有实现新的整体评估框架。

这不是遗漏，而是有意控制当前 PR 范围。当前 PR 只负责把 `multiview` baseline 做到可运行、可测试、可复现。

## 9. 运行时间与开销

四视图方法的开销明显高于 identity-only。

原因是：

1. 每个 view 都要单独编码 document。
2. `nlmeans` 是 CPU 图像处理，比较慢。
3. 四视图不是单纯 4 倍时间，实际会接近 5 到 6 倍。

本次观察到的运行时间大致为：

| 实验 | 耗时 |
| --- | ---: |
| identity-only 两个数据集 | 约 43 分钟 |
| InfoVQA 四视图 | 约 1 小时 16 分钟 |
| DocVQA 四视图 | 约 1 小时 23 分钟 |

因此，当前四视图适合作为离线实验 baseline，不适合直接作为高效率线上方案。后续真实退化图到位后，可以优先消融轻量组合：

```text
identity
identity + gaussian
identity + wiener
identity + nlmeans
identity + best_view
```

## 10. 遇到的问题与修复

之前运行 DocVQA 四视图时遇到过 OOM。原因是 MaxSim scoring 默认设备和 batch size 没有完全受控，导致显存压力过大。

修复方式：

```text
processor.score_multi_vector(..., batch_size=args.score_batch_size, device=DEVICE)
```

并新增：

```text
--score-batch-size
--device
```

这样可以明确指定 GPU 和 scoring batch size，降低 OOM 风险。
