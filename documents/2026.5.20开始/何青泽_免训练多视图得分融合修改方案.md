# 何青泽：免训练多视图得分融合修改方案与实验记录

> 版本：2026-05-23  
> 目标：在不训练 ColQwen2、不构造占位退化数据的前提下，实现可复用的多视图得分融合框架，并先用已有 clean 数据集验证它不会明显破坏原始检索性能。

## 1. 方案选择与当前约束

当前阶段还没有真实退化图，也没有明确的退化操作输入。因此本次实验没有使用项目里的 `DegradationPipeline` 构造 synthetic degraded benchmark，也没有把占位退化结果写成结论。

本次选择的主方案是 **免训练多视图得分融合**。核心思想是：不改 ColQwen2 模型参数，不训练任何额外模块，只在推理阶段为同一张文档图生成多个轻量视图，分别编码、分别打分，最后融合多个 score matrix。

这次先在 clean 数据上做稳定性验证，原因是：

1. 如果 clean 图上多视图融合导致指标大幅波动，那么后续即使在退化图上有提升，也难以判断是鲁棒性提升还是打分扰动。
2. 当前没有真实退化输入，直接跑占位退化流程会得到不可解释结论。
3. 多视图框架本身可以先实现好，后续真实退化图到位后只需要替换输入图片，不需要改模型或重写实验入口。

本次多视图包括：

| View | 含义 | 当前参数 |
| --- | --- | --- |
| `identity` | 原图，不做处理 | 无 |
| `nlmeans` | 轻量非局部均值去噪 | `h=5` |
| `gaussian` | 轻量高斯平滑 | `sigma=0.8` |
| `wiener` | Wiener 去模糊/复原视图 | `noise_power=0.01` |

## 2. 数据集与基线

沿用之前已经跑过、也已经在本机缓存过的 ViDoRe 子集：

| 数据集 | 样本数 | clean nDCG@5 | clean Recall@5 | clean MRR |
| --- | ---: | ---: | ---: | ---: |
| `vidore/docvqa_test_subsampled` | 500 | 0.5529 | 0.6160 | 0.5506 |
| `vidore/infovqa_test_subsampled` | 500 | 0.9107 | 0.9420 | 0.9041 |


## 3. 代码修改概览

新增文件：

```text
experiments/multiview.py
```

它只放与多视图相关的纯逻辑：

1. `validate_views()`：校验 view 名称，拒绝未知 view 和重复 view。
2. `get_view_preprocessor()`：把 view 名称映射成单图预处理函数。
3. `build_view_batch()`：对一个 batch 的 PIL 图片应用指定 view。
4. `normalize_view_weights()`：对被选中的 view 权重重新归一化。
5. `fuse_score_matrices()`：融合多个 view 的 score matrix。

修改文件：

```text
experiments/run_benchmark.py
```

新增能力：

| 参数 | 作用 |
| --- | --- |
| `--condition multiview` | 启用多视图评估流程 |
| `--views ...` | 指定要编码的视图，默认 `identity nlmeans gaussian wiener` |
| `--fusion max/mean/weighted` | 指定分数融合方式，默认 `weighted` |
| `--local-files-only` | 只读本地 Hugging Face 缓存 |
| `--model` / `--processor` | 支持本地模型路径，如 `./colqwen2-v1.0` |
| `--device` | 支持指定 `cuda:1`、`cuda:2` 等设备 |
| `--score-batch-size` | 控制 MaxSim 打分 batch，默认 16，降低显存风险 |

另外，如果只跑一个 subset，结果文件名会自动带上 subset 短名，避免两个 tmux 任务并行运行时互相覆盖平坦结果文件。

## 4. 代码逻辑说明

### 4.1 Query 端只编码一次

多视图只作用在文档图像端，query 文本没有必要重复编码。代码中 `encode_queries()` 按 `BATCH_SIZE` 分批执行：

```text
queries
  -> processor.process_queries()
  -> model(**inputs)
  -> all_q_vecs
```

这样可以避免多视图数量增加时 query 侧重复计算。

### 4.2 Document 端按 view 分别编码

每个 view 都会完整走一次 ColQwen2 图像编码流程：

```text
images
  -> build_view_batch(images, view)
  -> processor.process_images()
  -> model(**inputs)
  -> all_d_vecs_view
```

这一步没有修改 ColQwen2 内部结构，也没有训练参数。它只是改变输入图像的轻量预处理版本。

### 4.3 每个 view 单独计算 MaxSim

每个 view 的文档向量都会与同一份 query 向量计算一次 ColPali/ColQwen2 原始 late interaction 分数：

```text
scores_view = processor.score_multi_vector(
    all_q_vecs,
    all_d_vecs_view,
    batch_size=score_batch_size,
    device=DEVICE,
)
```

这里显式传入 `device=DEVICE` 很重要。第一次跑 DocVQA 时发现，如果不传 device，`score_multi_vector()` 会调用默认自动设备选择，实际跑到了 `cuda:0`，而模型本身在 `cuda:1`，导致打分阶段在错误 GPU 上 OOM。修复后打分跟随命令行指定的 `--device`。

### 4.4 Score-level fusion

多视图不在 embedding 层拼接，也不混合 token，而是在 score matrix 层融合：

```text
scores_final = fuse(scores_identity, scores_nlmeans, scores_gaussian, scores_wiener)
```

当前支持三种融合方式：

```text
max:      scores = max(scores_view_1, ..., scores_view_n)
mean:     scores = mean(scores_view_1, ..., scores_view_n)
weighted: scores = sum(weight_i * scores_view_i)
```

clean 稳定性实验默认使用 `weighted`，因为它以 `identity` 为主锚点，能降低轻量处理视图对 clean 输入的扰动。默认原始权重为：

| View | 原始权重 |
| --- | ---: |
| `identity` | 0.70 |
| `nlmeans` | 0.10 |
| `gaussian` | 0.10 |
| `wiener` | 0.10 |

如果只选择部分 view，会只对被选中的 view 归一化。例如：

```text
--views identity
```

实际权重就是：

```text
identity = 1.0
```

因此 identity-only 应当与 clean baseline 等价，这也是本次验证新代码正确性的关键对照。

## 6. 实验结果

### 6.1 identity-only 与 clean baseline 对齐

| 数据集 | 方法 | nDCG@5 | Recall@5 | MRR | 结论 |
| --- | --- | ---: | ---: | ---: | --- |
| docvqa_test_subsampled | clean baseline | 0.5529 | 0.6160 | 0.5506 | 原始结果 |
| docvqa_test_subsampled | multiview identity-only | 0.5529 | 0.6160 | 0.5506 | 等价 |
| infovqa_test_subsampled | clean baseline | 0.9107 | 0.9420 | 0.9041 | 原始结果 |
| infovqa_test_subsampled | multiview identity-only | 0.9107 | 0.9420 | 0.9041 | 等价 |

identity-only 与 clean baseline 对齐，说明新增 `multiview` 入口没有破坏原始 ColQwen2 编码、MaxSim 打分和指标计算流程。

### 6.2 四视图 weighted fusion 结果

| 数据集 | clean nDCG@5 | 四视图 nDCG@5 | nDCG 变化 | clean Recall@5 | 四视图 Recall@5 | clean MRR | 四视图 MRR |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| docvqa_test_subsampled | 0.5529 | 0.5555 | +0.0026 | 0.6160 | 0.6200 | 0.5506 | 0.5520 |
| infovqa_test_subsampled | 0.9107 | 0.9117 | +0.0010 | 0.9420 | 0.9420 | 0.9041 | 0.9056 |

平均 nDCG@5：

```text
clean baseline: 0.7318
四视图 weighted: 0.7336
变化: +0.0018
```

这个结果不能被解释为“已经提升了退化鲁棒性”，因为当前输入仍然是 clean 图。但它证明了一个前置条件：

> 在 clean 数据上，多视图 weighted fusion 没有造成明显性能破坏，且指标变化远小于 ±0.02 的稳定性阈值。

## 7. 问题与修复

### 7.1 OOM 原因

第一次 DocVQA 四视图实验失败在：

```text
processor.score_multi_vector(all_q_vecs, all_d_vecs)
```

原因是 `score_multi_vector()` 默认使用自动设备选择，不一定跟随模型所在的 `--device cuda:1`。当模型进程已经占用 GPU 显存时，打分阶段又在 `cuda:0` 分配较大的 MaxSim tensor，最终触发 OOM。

### 7.2 修复方式

修复点有两个：

1. 显式传入 `device=DEVICE`，保证打分和模型推理使用同一个命令行设备。
2. 新增 `--score-batch-size`，默认 16，降低 `einsum("bnd,csd->bcns")` 的显存峰值。

修复后 DocVQA 和 InfoVQA 都能完整跑完。

## 9. 结论

本次实现完成了一个可复用的免训练多视图得分融合框架，并在 clean 数据上完成稳定性验证：

1. `identity-only` 与 clean baseline 完全对齐，证明新入口没有改变原始检索逻辑。
2. 四视图 weighted fusion 在两个 clean 子集上均未造成明显退化，nDCG@5 变化控制在 `+0.0010` 到 `+0.0026`。
3. 方法目前不能声称解决真实退化鲁棒性问题，因为还没有真实退化图输入；但它已经满足后续接入真实退化图的工程条件。

当前阶段建议把该方法表述为：

> 在冻结 ColQwen2 的条件下，构建了一个测试时多视图表示与得分融合框架；clean 稳定性实验表明，该框架不会明显破坏原始 ViDoRe 检索性能，可作为后续真实退化图鲁棒性实验的主入口。

## 10. 后续接入真实退化图

后续真实退化图到位后，推荐新增一个数据读取入口，让 `images` 直接来自真实退化图，而不是 ViDoRe clean 图：

```text
真实退化图
  -> identity / nlmeans / gaussian / wiener
  -> ColQwen2 编码
  -> 每个视图 score_multi_vector
  -> max 或 weighted 融合
  -> nDCG@5 / Recall@5 / MRR
```

真实退化实验中建议优先比较：

| 方法 | 作用 |
| --- | --- |
| `degraded identity-only` | 真实退化输入下的下限基线 |
| `degraded weighted fusion` | 保守融合，避免个别视图误伤 |
| `degraded max fusion` | 激进融合，让每个 query-document pair 选择最高视图分数 |
| `clean baseline` | 上限参考 |

如果真实退化图上 `max fusion` 明显优于 `identity-only`，说明多视图中至少有某些复原视图能恢复有效匹配信号。如果 `weighted fusion` 更稳，则说明保留原始退化图作为 anchor 更适合实际场景。
