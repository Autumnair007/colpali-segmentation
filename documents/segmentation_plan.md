# 文档分割方案研究计划

> **负责模块**：`robust/segmentation/` — 文档图像分割预处理，在 ColQwen2 编码前介入  
> **核心目标**：通过在 `process_images()` 之前对文档图像做分割/前景提取，减少冗余视觉 patch，评估对检索性能（nDCG@5）的影响

---

## 1. 项目整体理解

### 1.1 项目做什么？

本项目研究 **ColPali/ColQwen2 视觉文档检索模型在退化场景下的鲁棒性**。ColQwen2 的工作原理是：

```
文档页面图像 → VLM 切成 patches → 每个 patch 得到 128 维嵌入 → MaxSim 延迟交互检索
```

项目不修改模型本身，而是在 `process_images()` **之前**插入预处理层：

```
文档图像 → [退化注入] → [复原/分割] → process_images() → 模型编码 → MaxSim 打分
```

### 1.2 四个子任务的关系

| 子任务 | 工作内容 | 与分割的关系 |
|--------|---------|-------------|
| A. 退化与复原 | 构建退化数据 + 复原算法 | 分割可与复原组合，先分割再复原 or 反过来 |
| **B. 文档分割（我）** | 提取文档主体，去除无用背景 | 核心工作 |
| C. 域外泛化 | 极端文档类型测试 | 分割方法需要对不同文档类型有泛化能力 |
| D. 评估与寻优 | nDCG@5 评估 + PSO 寻优 | 分割方法的参数可以用 PSO 优化 |

### 1.3 分割的切入点（代码层面）

分割在实验框架中的接入方式很简单，见 `experiments/run_benchmark.py`：

```python
if condition == "segmented":
    from robust.segmentation.document_seg import segment_document
    return lambda imgs: [segment_document(img) for img in imgs]
```

只需要实现一个 `PIL.Image → PIL.Image` 的函数，框架会自动在编码前调用。

## 2. 为什么分割对 ColQwen2 可能有用？

### 2.1 ColQwen2 的 patch 机制

ColQwen2 (Qwen2-VL) 将图像切成 **28×28 像素** 的 patches，经过 `spatial_merge_size=2` 后，每 2×2 patch 合并为一个 visual token。最终，一张文档图可能产生 **数百个** visual tokens，每个 token 产生一个 128 维嵌入向量。

**关键洞察**：背景区域（如扫描件的黑边、拍照文件的桌面、空白边距）也会产生 patch 嵌入。这些嵌入：
- 占用存储和计算资源
- 在 MaxSim 匹配时可能引入噪声（query token 可能错误 max-match 到背景 patch）
- 尤其在退化场景下（噪声/水印覆盖背景区域），可能严重干扰检索

### 2.2 理论上的收益

1. **减少噪声 patch**：将背景置白 → 背景 patch 嵌入变得"中性" → 降低错误匹配概率
2. **间接裁剪效果**：如果配合裁剪而非仅置白，可以减少 patch 数量 → 加速推理
3. **与退化的协同**：噪声/水印主要影响背景区域时，分割可以直接消除这些干扰

## 3. 现有方案分析（Baseline）

当前仓库中已有一个基础实现 `robust/segmentation/document_seg.py`：

```python
def segment_document(img, padding=5):
    # 1. 灰度化
    # 2. Otsu 二值化（自适应阈值）
    # 3. 形态学闭操作（15×15 矩形核）
    # 4. 找最大轮廓 → 取 bounding box
    # 5. box 外的区域置白
```

**优点**：简单快速，无需额外模型  
**局限性**：
- 只找最大轮廓的 bounding box → 无法处理多区域文档
- Otsu 阈值对低对比度文档可能失败
- 矩形 bounding box → 无法精确贴合不规则文档轮廓
- 对已经是白色背景的文档（大部分 PDF 截图）几乎无效果

## 4. 候选分割方法对比研究

以下是值得研究的几类方法，按复杂度递增排列：

### 4.1 传统图像处理方法（无需深度学习）

#### 方法 A：改进 Otsu + 连通域分析

```
灰度化 → 自适应阈值(而非全局Otsu) → 形态学操作 → 连通域分析 → 合并包围盒
```

| 项目 | 说明 |
|------|------|
| 核心改进 | 用 `cv2.adaptiveThreshold` 替代全局 Otsu，对光照不均更鲁棒 |
| 额外优势 | 连通域分析可以过滤小噪点，只保留大的文本/图表区域 |
| 计算开销 | 极低，纯 CPU，毫秒级 |
| 适用场景 | 有明显深色文档 + 浅色背景的扫描件 |
| 局限 | 对浅色文档、复杂背景效果差 |

#### 方法 B：GrabCut 交互式分割

```
初始矩形估计 → GrabCut 迭代 → 前景/背景掩码 → 背景置白
```

| 项目 | 说明 |
|------|------|
| 原理 | 基于 GMM 的前景/背景建模 + 图割优化 |
| 优势 | 能得到像素级精确的前景掩码，不限于矩形 |
| 计算开销 | 中等，每图约 50-200ms |
| 适用场景 | 文档边界不规则、有阴影/褶皱 |
| 局限 | 需要一个合理的初始矩形估计，迭代次数影响速度 |

#### 方法 C：边缘检测 + 透视变换

```
Canny 边缘 → 霍夫直线检测 → 找四边形 → 透视矫正 → 裁剪
```

| 项目 | 说明 |
|------|------|
| 原理 | 检测文档的四条边 → 做四点透视变换 → 得到矫正后的文档 |
| 优势 | 同时解决分割 + 倾斜问题（与同学 A 的 tilt 退化互补） |
| 计算开销 | 低-中，纯 OpenCV |
| 适用场景 | 拍照文档（有明确四边形边界） |
| 局限 | 对没有清晰四边的文档（如整页扫描）不适用 |

### 4.2 基于语义的分割方法（轻量深度学习）

#### 方法 D：基于颜色/纹理聚类的前景分离

```
图像 → 超像素(SLIC) → 特征提取(颜色+纹理) → KMeans聚类 → 前景/背景分类
```

| 项目 | 说明 |
|------|------|
| 原理 | 将图像分成超像素区域，对每个区域提取颜色直方图和 LBP 纹理特征，聚类分离 |
| 优势 | 不需要训练数据，对复杂背景有一定处理能力 |
| 计算开销 | 中等（超像素 + 聚类） |
| 适用场景 | 背景纹理与文档区别明显的场景 |
| 局限 | 聚类结果不稳定，需要调参 |

#### 方法 E：U²-Net / IS-Net 显著性检测

```
图像 → 预训练 U²-Net → 显著性图(0-1) → 阈值化 → 掩码 → 背景置白
```

| 项目 | 说明 |
|------|------|
| 原理 | 使用预训练的显著性目标检测模型提取前景 |
| 优势 | 对各种文档类型泛化能力强，像素级精确 |
| 计算开销 | 需要 GPU 推理，但模型较小（~44MB for U²-Net-lite） |
| 适用场景 | 几乎所有场景 |
| 局限 | 引入额外模型依赖；显著性 ≠ "文档区域" 的精确定义 |

#### 方法 F：文档版面分析模型（如 LayoutLMv3 / DocTR / YOLO-DocLayout）

```
图像 → 文档版面检测模型 → 检测框(text/table/figure/...) → 合并区域 → 裁剪或掩码
```

| 项目 | 说明 |
|------|------|
| 原理 | 用专门为文档设计的版面分析模型检测文本块、表格、图表 |
| 优势 | 语义级分割，能区分不同文档元素；与 ColPali 论文的"跳过 OCR pipeline"形成有趣对比 |
| 计算开销 | 较高，需要 GPU |
| 适用场景 | 复杂版面文档（多栏、混合图文） |
| 局限 | 复杂度高；本项目旨在评估"简单预处理"的效果，太复杂的方法可能偏离主题 |

### 4.3 方法汇总对比

| 方法 | 复杂度 | 额外依赖 | 泛化性 | 精度 | 推荐优先级 |
|------|-------|---------|-------|------|-----------|
| A. 改进阈值 + 连通域 | ★☆☆ | 无 | 低 | 低 | ⭐⭐ |
| B. GrabCut | ★★☆ | 无 | 中 | 中 | ⭐⭐⭐ |
| C. 边缘 + 透视变换 | ★★☆ | 无 | 低 | 高(特定场景) | ⭐⭐ |
| D. 超像素聚类 | ★★☆ | scikit-image | 中 | 中 | ⭐⭐ |
| E. U²-Net 显著性 | ★★★ | torch, U²-Net | 高 | 高 | ⭐⭐⭐⭐ |
| F. 文档版面分析 | ★★★★ | 专用模型 | 高 | 最高 | ⭐⭐⭐ |

## 5. 推荐实施路线

### 第一阶段：搞清 Baseline + 快速验证（1-2 天）

1. **跑通现有 baseline**：运行 `python experiments/run_benchmark.py --condition segmented`，记录 nDCG@5
2. **跑 clean baseline**：`--condition clean`，作为无分割的参照
3. **理解差异**：看分割后性能是提升还是下降，分析原因
4. **可视化**：抽几张图看看 `segment_document()` 实际分割的效果

### 第二阶段：实现 2-3 种改进方法（3-5 天）

建议实现的优先组合：

**方案一（推荐起步）**：改进传统方法
- 在 `document_seg.py` 中新增 `segment_document_v2()`
- 用自适应阈值替代 Otsu
- 增加连通域过滤（去小噪点）
- 增加 `mode` 参数支持"置白"和"裁剪"两种模式

**方案二（推荐重点研究）**：GrabCut 方法
- 新建 `grabcut_seg.py`
- 用边缘检测或 Otsu 的结果作为 GrabCut 的初始矩形
- 得到像素级前景掩码
- 可调参数：迭代次数、初始矩形估计策略

**方案三（如果时间允许）**：显著性检测
- 新建 `saliency_seg.py`
- 使用预训练的轻量模型（如 U²-Net-lite）
- 生成显著性图 → 阈值化 → 前景掩码

### 第三阶段：系统对比实验（2-3 天）

对每种方法在以下条件下测试：

```bash
# 不同条件 × 不同分割方法 的矩阵实验
for METHOD in baseline_otsu adaptive_thresh grabcut saliency; do
    # 1. 干净图上做分割
    python experiments/run_benchmark.py --condition segmented --seg_method $METHOD

    # 2. 退化图上做分割（分割是否能抵消退化影响？）
    python experiments/run_benchmark.py --condition seg_after_deg --deg heavy_noise --seg_method $METHOD

    # 3. 先复原再分割
    python experiments/run_benchmark.py --condition seg_after_restore --deg heavy_noise --rest nlmeans --seg_method $METHOD
done
```

> 注：上面的命令参数需要扩展 `run_benchmark.py`，增加 `--seg_method` 参数。

### 第四阶段：分析与撰写（1-2 天）

- 汇总所有条件下的 nDCG@5、Recall@5、MRR
- 生成对比图表
- 分析"分割在什么场景下有帮助、什么场景下反而有害"
- 结合 ColQwen2 的 patch 机制解释为什么

## 6. 你需要首先调研的关键问题

在确定最终方案之前，建议先弄清楚：

### 问题 1：ViDoRe 数据集的图像特点

```
需要看看 docvqa_test_subsampled / infovqa_test_subsampled 里面的图片长什么样。
如果都是干净的白底 PDF 截图 → 分割可能帮助有限
如果有扫描件、拍照文档、有背景的 → 分割可能有明显效果
```

### 问题 2：背景置白 vs 裁剪

```
置白：保持图像尺寸不变，背景变白 → patch 数量不变但背景 patch 变"中性"
裁剪：只保留文档区域 → patch 数量减少 → 推理更快 + 减少噪声匹配

哪种对 MaxSim 的影响更大？需要实验。
```

### 问题 3：分割精度 vs 检索性能的关系

```
分割太激进（把文档边缘也切掉）→ 丢失内容 → 性能下降
分割太保守（大量背景保留）→ 与不分割差异不大
需要找到平衡点，这可以用 PSO 优化（和同学 D 合作）
```

### 问题 4：是否需要 GPU

```
项目强调"无需重新训练"，所以分割作为预处理应该尽量轻量。
纯 OpenCV 方法（A/B/C）不需要 GPU，可以在 CPU 上快速运行。
如果使用深度学习分割（E/F），需要评估额外的推理开销是否值得。
```

## 7. 实施注意事项

1. **接口统一**：所有分割方法都应遵循 `PIL.Image → PIL.Image` 的接口，方便在 `run_benchmark.py` 中切换
2. **参数化**：每个方法的关键参数应暴露出来，供 PSO 寻优使用
3. **单元测试**：为每个新方法写测试，仿照 `tests/test_segmentation.py` 的模式
4. **不修改 `colpali_engine/`**：这是官方代码，所有新增代码放在 `robust/segmentation/` 下
5. **记录可视化样例**：保存分割前后的对比图，方便写报告和调试
